# IMPERIUM Neural Core — первый эксперимент

Собственная небольшая языковая нейросеть с обучением со случайных весов.
Код Transformer, байтовый токенизатор, цикл обучения и генерация находятся здесь.
PyTorch выполняет операции над тензорами, вычисление градиентов и обновление параметров.
Готовые модели, чужие обученные веса и внешние AI API не используются.
Архитектура основана на стандартном Transformer; это не заявление об изобретении нового типа сети.

**Состояние: исследовательский прототип.** Демонстрационный файл проверяет обучение.
Он слишком мал для освоения языка или получения надёжного помощника. Первые ответы
могут быть бессмысленными. Модуль пока не подключён к экрану приложения, рабочей
базе, документам или действиям сотрудников. В нём нет сервера, доступного из сети.

## Запуск на Windows

1. Установить [Python 3.12, 64 bit](https://www.python.org/downloads/), если его нет.
2. Скачать эту ветку репозитория, распаковать и открыть папку `ai-core`.
3. Запустить `START_WINDOWS.cmd`. При первом запуске создаётся отдельное окружение
   и устанавливается CPU-версия PyTorch из официального репозитория. Нужен интернет.
4. Выбрать **1** для проверки оборудования, затем **2** для 300 шагов демонстрационного обучения.
5. Выбрать **4** для экспериментального диалога; `/exit` завершает диалог.
6. Выбор **3** продолжает обучение из последнего сохранения ещё на 300 шагов.

Это начальный запуск на процессоре. После установки зависимостей обучение и генерация
работают локально; тексты никуда не отправляются. Скрипты Windows следует проверить
на целевом компьютере: локальная проверка проекта выполнялась на Linux/CPU.

### Видеокарта

Название ASUS TUF и возраст компьютера не определяют модель GPU или доступную память.
Команда проверки показывает ОЗУ, работоспособность CUDA, доступную видеопамять и,
при наличии `nvidia-smi`, сведения драйвера NVIDIA. Файл `hardware-report.json`
остаётся локально и исключён из Git.

Для ускорения установите подходящую сборку PyTorch через
[официальный подбор установки](https://pytorch.org/get-started/locally/): Windows,
Pip, Python, поддерживаемая CUDA. Выполните предложенную команду с
`.venv\Scripts\python.exe -m pip` вместо `pip3`; при замене уже установленной
CPU-сборки добавьте `--upgrade --force-reinstall`. Затем повторите проверку.
Не запускайте `INSTALL_WINDOWS.cmd` повторно после настройки GPU: это установщик CPU.

Автовыбор использует GPU только после успешной пробной операции. При недоступном
ускорении выбирается CPU. По умолчанию профиль `tiny`; при работоспособной CUDA
и минимум 3 GiB свободной видеопамяти — `small`. Это консервативная отправная точка,
не гарантия скорости и не измерение качества. Автоматического увеличения до `medium` нет.

## Команды

Команды выполняются из папки `ai-core`; в Windows вместо `python` можно использовать
`.venv\Scripts\python.exe`. В Linux создайте venv и установите `requirements.txt`.

```bash
python -m imperium_ai hardware --output hardware-report.json
python -m imperium_ai train --data data/demo.txt --output runs/demo.pt --steps 300
python -m imperium_ai train --data data/demo.txt --output runs/demo.pt --steps 300 --resume
python -m imperium_ai generate --checkpoint runs/demo.pt --prompt "Что такое этот проект?"
python -m imperium_ai chat --checkpoint runs/demo.pt
python -m unittest discover -s tests -v
```

`generate` продолжает переданный текст. `chat` добавляет метки диалога и перенос строки.

Свой корпус передаётся явно через `--data путь/тексты.txt`. UTF-8, максимум 16 MiB
на файл для этой первой версии. Абзацы разделяются пустой строкой; диалоговые
примеры имеют формат `User: ...` / `Assistant: ...`. Это обучение следующему токену
на всём тексте, а не отдельная процедура настройки поведения помощника.
Для собственной проверки используйте `--validation путь/проверка.txt`.
При отсутствии этого параметра последние 10% байтов удерживаются для проверки
до формирования окон. Окна обучения не пересекают границу; повторяющиеся тексты
по обе стороны раздела всё равно нужно удалять при подготовке корпуса.

Для продолжения требуется тот же корпус: отпечатки обучающей и проверочной частей
записаны в сохранении. Существующий файл не перезаписывается без `--resume`.
Параметры модели и оптимизатора загружаются из сохранения. `--steps` означает
добавочные шаги. При продолжении скорость обучения берётся из состояния оптимизатора.
Число потоков CPU можно уменьшить через `--threads 1`.

## Что измерять

В консоли и соседнем файле `.jsonl` сохраняются ошибки `train_loss` и `validation_loss`.
Снижение первой при росте второй — повод проверить переобучение. Метрика на
демонстрационном тексте не заменяет независимую проверку рабочих задач.
Модель сохраняется каждые 50 шагов и в конце; `--eval-every` меняет интервал.
Ctrl+C прекращает обучение. Продолжение возможно с последнего уже записанного
сохранения; шаги после него теряются. До первого сохранения продолжать ещё нечего.

Токен здесь — один байт UTF-8. Русская буква обычно занимает несколько байтов.
Контекст 128/256 токенов короткий; полноценной памяти разговора нет, каждый запрос
`chat` независим. Генерация обрезает старую часть запроса при превышении контекста.

При нехватке памяти уменьшите `--batch-size`; для нового опыта выберите
`--profile tiny --batch-size 1 --device cpu` и новый `--output`.
Размер уже обученной модели нельзя изменить параметром профиля при продолжении.

Сохранения загружаются с `weights_only=True`; всё равно используйте только доверенные
файлы. [Документация PyTorch по сохранению](https://docs.pytorch.org/docs/stable/notes/serialization.html).

## Следующий этап

Получить отчёт оборудования, подготовить существенно больший разрешённый корпус,
проверить качество на независимых запросах. Затем отдельно проектировать подключение
к «Империуму» с авторизацией и ограниченными операциями. Надёжность чтения договоров,
расчётов и выполнения команд должна проверяться отдельно от генерации текста.

Тексты фирмы помещайте в `data/private/`, веса — в `runs/`: обе папки исключены из Git.
Демонстрационный корпус написан для этого прототипа и не содержит реальных данных фирмы.
